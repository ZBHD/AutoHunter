# FOFA 轮换后的搜集进度与运行界面设计

日期：2026-07-17  
状态：待用户复核  
关联设计：`docs/superpowers/specs/2026-07-16-fofa-multi-key-rotation-design.md`  
关联目标：搜集阶段进度可视化、自动搜集表单收敛与 FOFA 多 Key 轮换反馈

## 1. 背景与目标

任务看板原本只需要表达“目标处置进度”。加入 FOFA 多 Key 运行时轮换后，自动搜集还需要回答三件事：当前是否正在工作、最近一次请求实际使用了哪个 Key、Key 池是否仍有可用容量。只把轮换当作普通错误会让用户误以为任务中断，只显示“当前 Key”又会在多任务共享池时产生误解。

本设计将运行界面拆为两层：任务指挥台负责当前任务的搜集与轮换摘要；系统设置负责全局 Key 池的长期管理。设计覆盖 FOFA 自动搜集以及其他自动搜索引擎的通用进度，但只有解析为 FOFA 的任务展示 Key 池信息。

## 2. 已确认的产品决策

- 采用“任务看板 + Key 池设置”双层运行界面。
- 任务看板显示 Key 的逻辑名称，不显示 Key 内容、脱敏前后字符串或 URL 编码值。
- 全局池采用现有 `FofaKeyRouter` 的粘性顺序轮换；同一业务请求每个 Key 最多尝试一次，最终成功后只推进一次业务分页游标。
- 任务级 `fofa_config.key` 是显式单 Key 覆盖，走单 Key Router，不参与全局池；界面标记为“任务专用 Key”。
- 空池继续回退旧 `fofa.key`、旧引擎配置或 `FOFA_KEY`，前端以只读“Legacy Key”呈现。
- 单个 Key 的限流、每日额度或认证失败先触发切换；瞬时网络/端点故障结束本轮并保留当前游标；只有整个池不可用才影响任务状态。
- 已有目标时，Key 轮换和后台补队列只更新搜集状态带，不重置主处置进度。
- 非 FOFA 自动搜索引擎使用通用搜集进度，不显示 FOFA Key 池字段。

## 3. 信息架构

### 3.1 任务指挥台

任务头部保留三层：

1. **身份层**：任务名称、运行状态、任务模式、目标来源、搜索引擎、并发和模型。
2. **进度层**：进度环与主进度条。没有目标且自动搜集处于活动阶段时显示“搜集进度”；出现目标后稳定显示“处置进度”。
3. **搜集状态层**：当前阶段、最近成功使用的 Key 名称、池可用数量、轮换摘要或等待时间。

自动搜集任务启动后，即使还没有 WebSocket 事件，也由启动响应提供 `initializing` 状态，立即显示“正在初始化搜集引擎”。`initializing` 和 `querying` 使用不确定动画；有分母的预筛、评分、过滤阶段使用粗粒度确定进度；没有可靠分母时不伪造精确百分比。

任务页区分两个 Key 名称：

- `last_key_name`：本任务最近一次成功请求使用的 Key。
- `active_key_name`：全局池的粘性游标，只在设置页作为池级当前项展示。

这样，一个任务不会因为另一个任务切换了共享池而误显示“本任务已切换”。

### 3.2 设置页

系统设置新增独立的 `FOFA Key 池` 面板，复用 LLM Provider 池的列表交互：新增、编辑、删除、上下移动、启用/停用、单项检测和一键健康检查。

面板顶部显示“可用 N/M”和全局粘性 Key 名称。每行显示排序、逻辑名称、统一脱敏占位、运行状态、冷却倒计时、最近检测延迟和操作按钮。运行状态使用以下语义：

- `ready`：可参与轮换。
- `rate_limited`：指数退避冷却，到期自动回池。
- `daily_cooldown`：每日额度冷却，到期自动探测。
- `daily_suspended`：连续每日额度失败后长期阻断，检测或替换后恢复。
- `auth_invalid`：认证/权限阻断，检测成功或替换后恢复。
- 手动停用：不参与轮换，检测成功也不自动启用。

健康检查并行检测所有已配置 Key，包括手动停用项；设置发生变化后旧健康结果标记为 `stale`。空池的 Legacy Key 为只读行，不允许排序或编辑真实值。

### 3.3 新建与编辑任务

| 目标来源/引擎 | 展示字段 |
| --- | --- |
| 自动搜集 + FOFA | 搜索引擎、搜集方式、搜集语法/意图、全局 Key 池或任务专用 Key |
| 自动搜集 + 其他引擎 | 该引擎现有配置和通用搜集字段，不显示 FOFA Key 池 |
| 两者 + FOFA | 自动搜集字段、手动目标、全局池/任务专用 Key |
| 手动清单 | 仅手动目标和处置配置 |
| 单站协作 | 主目标 URL、协作重点和处置配置 |

切换来源或引擎时不丢弃用户已经填写的字段；提交时只发送当前模式适用的字段。任务编辑中，服务端已存在的任务专用 Key 显示为“已配置，留空保留原值”。

## 4. 状态与事件契约

### 4.1 任务快照

`_public_fofa_config()` 在保留现有端点、分页和查询字段的基础上增加：

```text
key_source: global_pool | task_override | legacy
last_key_name: string
pool_available: integer
pool_total: integer
pool_state: ready | cooling | blocked
last_rotation: {
  from_key_name: string,
  to_key_name: string,
  reason: auth | rate_limit | daily_limit
}
cooldown_until: ISO-8601 timestamp | null
```

Key 名称是逻辑标签；所有凭据内容仍只存在服务端运行时和受保护的持久化配置中。

### 4.2 WebSocket 事件

- `collector_phase`：初始化、查询、预筛、评分、目标过滤、补充情报和入队等搜集进度；附带 `engine`、`key_name`、候选/过滤数量等非敏感摘要。
- `fofa_key_rotated`：当前 Key 失败后切换到备用 Key；附带来源名称、目标名称、结构化失败类型和重试序号。
- `fofa_pool_waiting`：所有候选 Key 均处于冷却，附带最早恢复时间和池摘要。
- `fofa_pool_blocked`：所有 Key 均认证失效或每日额度长期阻断，附带汇总原因，不附带密钥内容。

任务事件只记录由该任务请求触发的轮换。设置页的全局池状态通过 Key API 与健康检查获取，不依赖某一个任务的事件流。

### 4.3 状态映射

| 运行状态 | 看板表现 | 主任务影响 |
| --- | --- | --- |
| 初始化/查询 | 蓝色不确定动画，显示最近或当前 Key | 任务继续运行 |
| 单 Key 失败后切换成功 | 信息色“已切换到备用账号”，显示上一 Key 原因 | 不暂停，不回退处置进度 |
| 全池冷却 | 警告色、静态状态带、最早回池倒计时 | 已有队列继续处置；搜集等待 |
| 全池认证/额度阻断 | 错误色、阻断原因和进入设置入口 | 自动暂停任务 |
| 无新增资产 | 中性色“本轮无新增”，保留下一轮运行语义 | 任务不视为失败 |

## 5. 数据流与并发边界

1. `POST /api/tasks/{id}/start` 将任务置为 `running`；自动搜集任务在同一事务写入 `initializing`，响应立即携带该状态。
2. `collector.refill()` 在解析查询和发起引擎请求前写入搜集阶段；FOFA 请求通过 `settings_service.fofa_router_for_task(task)` 获取全局池 Router 或任务级单 Key Router。
3. Router 在锁内读取候选快照与游标，释放锁后执行网络请求；成功/失败写回使用 Key 名称和配置指纹做条件校验，避免设置修改覆盖新配置。
4. 单次业务请求最多尝试一圈 Key。某个备用 Key 成功时，调用方只接收一次成功结果并推进一次分页游标。
5. Router 的状态变化写入 `fofa_keys` 或任务 `fofa_config`，同时通过事件总线发布脱敏事件；看板通过 WebSocket 增量更新，断线后由 `/board` 快照恢复。
6. 设置页的增删改、排序或替换使旧配置指纹失效并重建 Router；重新排序按名称保留当前粘性项，删除当前项则移动到下一个候选。

其他搜索引擎沿用现有 Collector 路径，只接收通用 `collector_phase`，不访问 FOFA Key Router。

## 6. 组件与模块边界

### 后端

- `app/fofa/router.py`：选择、轮换、失败分类、冷却和状态回写；不负责任务进度文案。
- `app/settings_service.py`：Key 池解析、Legacy 回退、缓存/指纹和脱敏 CRUD。
- `app/api/settings.py` 与 DTO：Key 池接口、逐项检测、一键检测和健康结果。
- `app/agents/collector.py` 与 `app/orchestrator.py`：阶段事件、任务级摘要和任务状态转换。
- `app/api/tasks.py`：公开脱敏的任务快照；保持观摩角色只见通用状态。

### 前端

- `frontend/src/fofaKeys.js`：状态徽标、可用数量、排序和健康结果纯函数。
- `frontend/src/components/FofaKeysPanel.vue`：Key 池列表、操作与状态展示。
- `frontend/src/views/SettingsView.vue`：挂载 Key 池面板，保留端点、分页和默认搜集参数。
- `frontend/src/views/BoardView.vue`：任务级搜集/轮换摘要、进度模式和事件状态机。
- `frontend/src/views/CreateView.vue` 与 `frontend/src/components/TaskEditModal.vue`：复用目标来源和引擎分流规则。
- `frontend/src/style.css`：状态色、冷却倒计时、移动端布局和 `prefers-reduced-motion`。

## 7. 错误与隐私处理

FOFA 错误仍按 `auth`、`rate_limit`、`daily_limit`、`transient` 分类。每日额度优先于通用 quota 或账号错误，避免把额度耗尽误判为认证失败。日志、事件、API 错误和健康检查结果统一脱敏，禁止保留明文 Key 或编码后的 Key。

前端收到未知状态时回退到中性“搜集状态更新中”，不把原始异常字符串直接渲染到页面。动画遵守 `prefers-reduced-motion`，冷却计时使用服务端 UTC 时间戳换算，避免依赖浏览器本地时钟格式。

## 8. 测试与验收

### 后端

- Router：粘性选择、顺序切换、单圈尝试上限、四类失败、冷却恢复、全池耗尽、并发幂等、配置指纹竞态和脱敏。
- Collector：启动初始化、单 Key 失败后备用 Key 成功、分页只推进一次、全池等待、全池阻断暂停、任务级覆盖和其他引擎旁路。
- 设置 API：CRUD、排序、重复名称、空 Key 校验、启停、单项/一键检测、Legacy 回退和旧接口兼容。
- 任务快照/事件：`last_key_name` 与全局 `active_key_name` 分离，轮换事件只归属触发任务，观摩响应脱敏。

### 前端

- Key 池列表加载、添加、编辑、删除、排序、启停、单项检测和健康结果过期。
- 初始化、正常搜集、成功轮换、全池等待、全池阻断和无新增资产状态。
- WebSocket 局部事件合并不清空已有计数、最近 Key 或冷却信息。
- 自动搜集/手动/两者/单站协作与 FOFA/其他引擎的字段显隐。
- 移动端不重叠、无布局跳动，生产构建通过，`prefers-reduced-motion` 下无循环动画。

### 验收场景

1. 主账号限流、备用账号成功时，任务不中断并显示切换原因。
2. 所有 Key 冷却时显示最早恢复时间，已有队列继续执行。
3. 所有 Key 持久阻断时自动暂停并能进入设置页恢复。
4. 刷新或 WebSocket 重连后，Key 名称、池状态和搜集阶段一致。
5. 页面、事件、日志和 API 响应中不存在任何明文或 URL 编码后的 Key。

## 9. 非目标

- 不把所有搜索引擎扩展为通用凭据池。
- 不改变 FOFA 查询语法、分页语义和任务级配置格式。
- 不自动打开用户手动停用的 Key。
- 不新增独立的跨任务 FOFA 监控页；全局长期管理集中在系统设置。
